### R16 — new package fields default to empty tuples

`exclusion_ids: tuple[str, ...] = ()` and `preference_ids: tuple[str, ...] = ()`.

Repository evidence supports this and contradicts nothing: `CanonicalIntentPackage` is a
`FrozenModel` (`extra="forbid"`), is **derived on every call**, and is **never persisted in
the event log**, so no stored payload can lack the fields and no consumer can be constructed
from historical data missing them. Defaults therefore cost nothing and keep every existing
construction site valid. `boundary_ids` keeps its current type and is never removed, so no
current consumer loses it.

### R17 — the seam, concretely

```python
# application/semantic_governance.py  (NOT frozen)
def record_intent_object(self, obj: SemanticObject) -> StoredEvent:
    self._require_project(obj.project_id, "intent object")
    validate_relations(self.state(), obj)          # forward-only; raises on illegal
    event = self._append(EventType.SEMANTIC_OBJECT_RECORDED,
                         SemanticObjectPayload(object=obj), "intent object")
    for rel in obj.relations:                       # I-DERIV-1, same governed call
        if rel.relation_type is RelationType.DERIVED_FROM:
            self.derive(obj.id, rel.target_id)
    return event
```

Covers every new non-synthesis intent-object write and is the seam multi-type synthesis will
call later. It does **not** cover the frozen certified path; that gap is pinned by a test (see
controls) rather than left implicit.

## Test plan

**Relation legality** — one test per matrix row asserting the legal pair passes and at least
one illegal pair is rejected, plus:
- `DERIVED_FROM` targeting `INTENT` is rejected (`I-SEP-1`) — relevance is never basis;
- `EXCLUDES` from a non-`NON_GOAL` source is rejected;
- `SERVES` from `INTENT` is rejected (the root serves nothing);
- an unknown/unresolvable target id is reported, not silently ignored.

**NonGoal enforcement**
- canonical `NonGoal` + canonical excluded `Requirement` → `EXCLUDED_BY_NON_GOAL` blocker;
- non-canonical either side → no blocker;
- out-of-scope `NonGoal` → no blocker (`I-EXCL-2`);
- exclusion of a `Constraint` and of a `Goal` both blocked.

**Delivery split**
- `exclusion_ids` contains only `NonGoal`; `preference_ids` only `Preference`;
- `I-STR-1`: a `Preference` never appears in `obligation_ids`;
- **compatibility pin**: `boundary_ids == tuple(sorted(exclusion_ids + preference_ids))`;
- the two existing assertions (`test_package.py:107`, `test_intent_synthesis_replay.py:922`) pass unchanged.

**Admission seam (R17)**
- an object with an illegal relation is refused by `record_intent_object()` and **no event is appended**;
- a legal object is written, and one `DERIVATION_RECORDED` accompanies each `DERIVED_FROM` (`I-DERIV-1`);
- replaying a legacy ledger whose objects carry now-illegal relations succeeds untouched (forward-only);
- **certified-path compliance pin**: every relation shape the frozen Slice-1 path can emit (`Requirement ──DERIVED_FROM──▶ Claim`) is legality-clean, so the frozen path cannot drift unnoticed.

**ConstraintFacet (R19)**
- each facet's relaxation rule is distinct and representable;
- `EXTERNAL_MANDATE` without external provenance + `AuthorityRecord` is refused;
- `PROJECT_BOUNDARY` is changeable by a governed human authority act; `EXTERNAL_MANDATE` is not;
- `EVIDENCE_BOUND` is unaffected by a decision or preference and changes only with its basis;
- a `Constraint` deserialized without `facet` replays as `None`.

**ProjectDecision (R18)**
- `kind` still serializes as `"DECISION"`;
- a `DECISION` is **rejected** as a `CONSTRAINS` source;
- a `Constraint` may name a `DECISION` via `DERIVED_FROM`, and the chain must continue past it to evidence (`I-BASIS-2`);
- `Decision is ProjectDecision` (alias identity);
- a decision with no consequence relation is reported inert (`I-DEC-1`, report only in IE2.1);
- `I-DEC-2`: a `DECISION` never appears in `obligation_ids`.

## Mutation / negative controls

The suite must kill each of:

1. `EXCLUDES` legality dropped — any source may exclude;
2. `DERIVED_FROM → INTENT` permitted (collapses R2's two axes);
3. exclusion blocker deleted;
4. exclusion blocker ignores scope;
5. exclusion blocker fires on non-canonical objects;
6. `Preference` admitted into `obligation_ids`;
7. `exclusion_ids` and `preference_ids` swapped;
8. `boundary_ids` redefined as something other than the union (drift);
9. `Constraint.facet` made required (replay break, see below);
10. `EXTERNAL_MANDATE` accepted without external authority;
11. `SERVES` made non-transitive (would force restating whole chains);
12. legality validated at parse time rather than admission time;
13. **`validate_relations()` detached from the seam** — the law reverts to test-only and nothing in production enforces it;
14. `record_intent_object()` writes the object but skips its derivation edges (breaks `I-DERIV-1`);
15. `DECISION` permitted as a `CONSTRAINS` source (Decision acquires Constraint semantics — R18);
16. `DECISION` accepted as a *terminal* basis, so a chain stops at a choice instead of reaching evidence;
17. `ConstraintFacet` relaxation rules collapsed — `EXTERNAL_MANDATE` waivable by project authority;
18. `SUPPORTS`/`CHALLENGES` activated as a second truth alongside `Evidence.*_claim_ids` (R20);
19. `SUPERSEDES` relation wired to drive lifecycle instead of the durable records (R20);
20. `I-PROV-1` reverted to prose/keyword inspection of statements (R21).

## Migration and replay risks

**The significant one: where legality is enforced.** Existing serialized objects may already
carry relations that the new matrix calls illegal — nothing has ever validated them. If
`validate_relations()` runs at parse or reduce time, historical replay breaks and the event
log stops being replayable, which would violate the property MR4–MR6 certified. Legality must
therefore be **forward-only**: enforced at admission/canonicalization of *new* objects, never
during reconstruction. Mutation control 12 exists to keep it that way, and the IE2.1 test
suite must include a replay of an existing ledger containing only legacy relations.

**`Constraint.facet` must stay optional.** Old events have no facet; a required field breaks
`parse_event`. It defaults to `None` and is required only when canonicalizing a new
Constraint. Mutation control 9 pins this.

**Enum additions are safe.** No historical event contains `SERVES` or `EXCLUDES`, and
`RelationType` is a `StrEnum` parsed by value.

**The class rename is serialization-neutral.** `kind: Literal[SemanticKind.DECISION]` is what
round-trips; the Python class name never appears in the log. The deprecated alias keeps the
`SemanticObject` union and existing imports working.

**`boundary_ids` carries no replay risk at all** — `CanonicalIntentPackage` is derived on
every call and never stored.

**Certification impact: none expected.** Slice 1 synthesizes only `REQUIREMENT` with a single
`DERIVED_FROM` relation to a claim, which stays legal under the matrix. The certification
exam asserts exactly that relation shape, so it should pass untouched — but the full
certification suite is gated and must be re-run offline, and frozen hashes re-verified,
before IE2.1 is accepted.

## Is IE2.1 implementation-ready?

**Yes, with one caveat that is documented rather than hidden.**

Resolved by this repair: the legality law now has a production seam (R17); the
Decision/Constraint inconsistency is gone (R18); the facet classifies behaviour rather than
topic (R19); overlapping representations have single owners and the pre-existing
derivation divergence is stated (R20); the provenance invariant is structurally checkable
(R21); NonGoal enforcement is scoped to explicit edges (R22); and the package split is
approved with backward-safe defaults (R16).

The caveat: **the certified Slice-1 synthesis path is not routed through the seam in IE2.1**,
because it is frozen. IE2.1 therefore enforces legality on every new non-synthesis write and
*verifies* — rather than enforces — that the frozen path stays compliant. Routing synthesis
through the seam, and any backfill of `DerivationEdge` for historical Requirements, are
reviewed compatibility changes belonging to the multi-type synthesis slice.

No further design decisions are outstanding. Implementation may begin on approval.
