# IE2.2 — Basis vs Relevance invariants (normative)

Base: `5cba86df269b9abe867dc705f65ef069c72ed90c` (IE2.1 closed). Incorporates R31–R41.
Design only.

## 1. Audit — what the repository does today

Grounded in code at this head.

**Basis and relevance exist as vocabulary; nothing checks completeness.** IE2.1 validates
that a relation is *permitted*. Nothing anywhere walks a basis chain or a relevance path.

**The two planes have genuinely different lifeness, and no abstraction spans them:**

| plane | liveness is | existing mechanism |
|---|---|---|
| `state.objects` | `lifecycle is ACTIVE` and `authority ∉ {REJECTED, SUPERSEDED}` | `closure._is_current` |
| `state.semantic.claims` | the asserting `ASSERT_CLAIM` judgment is active | `semantic_view.active_judgment_ids` |
| `state.semantic.evidence` | **no liveness concept at all** | — |

IE2.2 reuses these three and invents no fourth.

**Evidence supersession does not invalidate claims.** `domain/evidence.py`: lineage "carries
NO semantic authority: a claim citing a superseded version is neither superseded nor flagged
by it." IE2.2 does not overturn this.

**The certified Slice-1 Requirement is `PROPOSED`**, carries **no `SERVES` edge**, and its
basis claim carries **`INFERRED`** authority. All three facts matter below.

**Scope applicability is already duplicated.** Four private definitions —
`closure._object_applies`, `application/handoff_v2._applies`, `package._applies`,
`domain/handoff_v2._object_applies` — plus inline copies in at least four more modules, all
implementing `scope == () or scope in obj.scope`. This is a pre-existing drift risk that R39
makes relevant (§7).

## 2. The central law (R32)

**Canonical authority is the baseline. Evidential proof is an additional requirement for
some kinds, never a substitute and never mutually exclusive.**

```
EVERY canonical intended-state object   →  legitimate authority           (baseline)
SOME kinds, by semantic meaning         →  + a lawful evidential basis    (additional)
```

IE2.1 already guarantees the baseline at canonicalization: human author, authenticated
actor, covering `AuthorityRecord`. IE2.2 adds the evidential requirement only where the
object's meaning is a claim about the world.

The failure this shape avoids: forcing empirical evidence into human choices. "We will not
build video calling" is not a claim evidence could confirm, and fabricated evidence to
satisfy an invariant is worse than no invariant. Multiple compatible proof sources may
coexist — a Goal may carry evidential rationale without being required to.

## 3. Invariants

**Basis**
- `I-BASIS-1` — every **active, canonical, applicable** object of a kind requiring evidential proof (§4) has a `DERIVED_FROM` chain terminating lawfully (§5).
- `I-BASIS-2` — every chain terminates at a lawful terminal: a qualifying `SemanticClaim` (§5) or a qualifying canonical `ProjectDecision` (§6).
- `I-BASIS-3` — `ASSUMPTION` may never appear anywhere in a basis chain, terminal or intermediate.
- `I-BASIS-4` — no `DERIVED_FROM` cycle (§8).

**Relevance**
- `I-REL-1` — for evaluated delivery scope `S`, every active canonical object applicable to `S`, except the root `INTENT`, has a `SERVES` path reaching the canonical root Intent for `S`.
- `I-REL-2` — every object on that path is **applicable to `S`** (§7). Not containment.
- `I-REL-3` — no `SERVES` cycle (§8).

**Root**
- `I-ROOT-1` — for evaluated scope `S`, **exactly one** active canonical `Intent` applicable to `S` (§6).

**Separation** — `I-SEP-1` (`DERIVED_FROM` never targets `INTENT`) is enforced in IE2.1.

## 4. Per-kind grounding (R40)

Baseline for every row: canonical authority, established at canonicalization (R33).

| kind | evidential basis | relevance | terminal for others |
|---|---|---|---|
| `INTENT` | not required; root | n/a — it *is* the root | never (`I-SEP-1`) |
| `GOAL` | optional | required | intermediate |
| `OUTCOME` | optional | required | intermediate |
| `REQUIREMENT` | **either**: directly authoritative, or evidentially derived (R37) | required | intermediate |
| `CONSTRAINT` / `PROJECT_BOUNDARY` | not required | required | intermediate |
| `CONSTRAINT` / `EVIDENCE_BOUND` | **required** | required | intermediate |
| `CONSTRAINT` / `EXTERNAL_MANDATE` | **required**, plus attestation (§10) | required | intermediate |
| `NON_GOAL` | not required | required | never a basis |
| `PREFERENCE` | not required | required | never a basis |
| `DECISION` | optional | required | **lawful authoritative terminal** (§6) |
| `ASSUMPTION` | n/a — a recorded presumption | **not required** | **never**, at any position |
| `CONTRACT` | legacy; IE2.2 adds no new semantics | legacy | legacy |

`REQUIREMENT` (R37): absence of `DERIVED_FROM` is lawful for a directly authorized
requirement. If it *declares* `DERIVED_FROM` edges, those must obey the basis rules — an
object does not get to cite a basis and then be excused from its validity.

`ASSUMPTION`: no `SERVES` path is forced merely because the frozen synthesis kind set happens
to include it. Its dependency on intent is expressed by `AFFECTS`, which IE2.1 already
permits and IE2.3 will traverse.

## 5. The evidential terminal (R35), and what verification found

Lawful evidential terminal — a `SemanticClaim` such that **all** hold:

```
claim exists in state.semantic.claims
AND claim.created_by_judgment_id ∈ active_judgment_ids(state.semantic)
AND every id in claim.evidence_ids exists in state.semantic.evidence
AND claim.authority ∈ {OBSERVED, CANONICAL}        ← explicit set, never an ordering
```

Evidence must be **present**, not newest; existing supersession law is untouched.

**Verification against the repository, as R35 required. No invariant contradicts the set, but
two facts must be recorded before it is locked.**

**(a) The certified Slice-1 basis claim is `INFERRED`.** Under this rule it is *not* a lawful
evidential terminal. Nothing breaks today, because the certified Requirement is `PROPOSED`
and canonical rules do not reach it. But the consequence is real and should be stated plainly:
**a Requirement resting on a model-inferred claim cannot be canonicalized until a human
canonicalizes the claim.** That is the correct behaviour under Law 5 — a model's inference
must not silently become the factual premise of canonical intent — and a legal exit exists,
since a human with covering authority may assert the claim canonically through the existing
governance path. It is nonetheless a workflow step the Intent pipeline does not have today.

**(b) `OBSERVED` is not restricted to human assertion.** `admission.py` refuses only
`CANONICAL` claims from non-human reasoners; a model may assert `OBSERVED`. Including
`OBSERVED` therefore admits machine-recorded observations as grounding. This is defensible
because the baseline still holds — a human authorizes the canonical *object* in every case —
so the guarantee is "a human authorized this intended state, grounded in a recorded
observation", not "a human verified the observation". Stating it that way keeps the claim
truthful. If that is too weak, the alternative is `{CANONICAL}` only, which would require a
human to canonicalize every grounding claim.

## 6. Authoritative terminals and the root (R31, R34)

**`ProjectDecision` is a lawful terminal** when it is current, `CANONICAL`, and applicable to
the evaluated scope with its own relevance path. The authorized project choosing something is
itself the ground; fabricating evidential basis for a choice would be the same error as
demanding evidence for a `NonGoal`. A Decision may optionally carry evidential rationale, and
if present it remains traceable and must be valid.

Preserved from IE2.1: a Decision is not a Constraint, never sources `CONSTRAINS`, and never
enters `obligation_ids`.

**Root is per evaluated delivery scope (R31), not per project.** For scope `S`, exactly one
active canonical `Intent` applicable to `S`. So:

```
Intent-A scope=("billing",)  +  Intent-B scope=("security",)    legal
Intent-global scope=()       +  Intent-billing scope=("billing",)
        → evaluating "billing" sees two applicable roots → readiness blocker
```

Multiplicity blocks readiness; it never fails replay. Sub-intents stay unexpressible —
`SERVES` still excludes `INTENT` as a source.

## 7. Scope applicability (R39)

For evaluated scope `S`, every object on a `SERVES` path must **apply to `S`** under
Foundry's existing semantics — `scope == () or S in scope` — not literal containment. A
scoped Requirement may serve a project-wide Goal:

```
Requirement scope=("billing",) → Goal scope=() → Intent scope=()      legal
```

**The audit found this rule already duplicated in four private helpers plus inline copies.**
IE2.2 must not add a fifth. Recommendation: extract one shared domain helper taking a scope
tuple, use it in IE2.2c, and migrate existing call sites in a separate mechanical change
rather than smuggling a refactor into an invariant slice.

## 8. Cycles (R41)

New `SERVES` / `DERIVED_FROM` cycles are refused at forward admission, with bounded
visited-set traversal so a pre-existing historical cycle terminates and reports rather than
hangs.

**Stated without overselling:** under IE2.1's forward-only law a relation target must already
exist, so a purely new cycle is difficult to form sequentially through the seam. The check
matters for legacy graph shapes, dangling or re-introduced ids, and future write paths that
do not go through today's seam. It is cheap insurance, not the solution to a failure the
current seam readily produces.

Historical cycles replay and become deterministic blockers.

## 9. Authority is established, not leased (R33)

Authority is checked at the governance act that establishes canonical state. A canonical
object does **not** become invalid because the authorizing human's `AuthorityRecord` was later
retired:

```
Alice authorized Monday → Alice makes a canonical Decision Monday → Alice's authority ends Friday
⇒ the Monday decision stands until explicitly superseded, amended or reconciled
```

Consequences for the design: basis traversal does **not** re-prove authority for objects
already `CANONICAL` — being canonical *is* the record of that act, and the durable admission
event retains the author for audit. No projected authorship store is needed. Historical
canonical objects remain subject to the new basis/relevance readiness laws (§10) but are never
retroactively stripped of authority for a missing old record.

## 10. Historical readiness blockers (R38)

History always replays. Historical canonical objects that fail present-day rules are valid
history and not delivery-ready. Proposed deterministic blockers, each with a legal exit:

| code | condition | exit |
|---|---|---|
| `MULTIPLE_CANONICAL_ROOTS` | >1 canonical Intent applicable to `S` | supersede or re-scope one |
| `UNGROUNDED_CANONICAL_OBJECT` | evidential kind with no lawful terminal | canonicalize the claim, or supersede |
| `DEAD_BASIS` | chain reaches a claim whose judgment is inactive | re-assert the claim, or supersede |
| `UNLAWFUL_BASIS_AUTHORITY` | terminal claim outside `{OBSERVED, CANONICAL}` | human canonicalizes the claim |
| `ASSUMPTION_IN_BASIS` | assumption anywhere in a chain | re-express as `AFFECTS`, supersede |
| `ORPHANED_CANONICAL_OBJECT` | no `SERVES` path to the root for `S` | add relevance via a superseding object |
| `BASIS_CYCLE` / `RELEVANCE_CYCLE` | historical cycle | supersede a participant |

Every exit is an existing lifecycle operation. None requires editing history.

## 11. `ConstraintFacet` proof (R36 — decision B1)

`AuthorityRecord` is **not** modified. For `EXTERNAL_MANDATE`, the canonical Constraint,
admitted by an authorized human carrying that facet, **is** the attestation. IE2.2 additionally
requires a lawful evidential basis.

The truthful guarantee, stated as it will appear in any record:

> An authorized human attested that this is externally imposed, **and** a valid evidential
> basis exists.

Not: "Foundry proved the source is external." IE2.1's rule that `HUMAN` provenance cannot
masquerade as `EXTERNAL_MANDATE` is preserved. No `source_ref` keyword heuristics.

## 12. Certified Slice-1 compatibility

Unchanged and untouched. The certified Requirement is `PROPOSED`, so canonical rules do not
reach it; basis validation reads **object-local `DERIVED_FROM` relations**, never
`DerivationEdge`, so the two parent-id conventions never need reconciling here. Normalization
stays in IE2.3. Nothing is backfilled.

## 13. Enforcement layer per rule

| rule | layer |
|---|---|
| relation legality, `I-SEP-1` | admission (IE2.1, done) |
| `I-BASIS-4`, `I-REL-3` (new cycles) | **admission** |
| `I-BASIS-1/2/3`, `I-REL-1/2` for a **new canonical** object | **admission, gated on `CANONICAL`** |
| facet proof (§11) | **admission, gated on `CANONICAL`** |
| `I-ROOT-1` | **closure/readiness** — history may hold several roots |
| all historical failures (§10) | **closure/readiness** |

Non-canonical objects stay unconstrained: a Requirement proposed before its Goal exists is
normal incremental work.

## Frozen for IE2.2a

Everything frozen for IE2.1 — the certified Intent vertical, `tests/certification/**`, both
certification records and their evidence, all of `model_runtime/` — plus
`domain/relation_legality.py` and the `INTENT_OBJECT_ADMITTED` contract, which IE2.2a consumes
unchanged. Hash-verified before and after.

## RED tests

1. `ModuleNotFoundError: foundry.domain.graph_cycles`.
2. Admitting `B ──SERVES──▶ A` when `A ──SERVES──▶ B` already exists **succeeds today** → asserting refusal fails.
3. Same for `DERIVED_FROM`.
4. A three-node `SERVES` cycle is admitted.
5. A self-edge (`X ──SERVES──▶ X`) is admitted.

## Test plan

- two-node and three-node cycles refused for both relation types, with **no event appended**;
- a legal DAG (diamond: two paths to one root) is admitted — the check must not confuse re-convergence with a cycle;
- a self-edge is refused;
- **termination**: a state already containing a cycle does not hang the walk, asserted with a timeout-bounded test;
- historical replay of both certified ledgers unchanged;
- a legacy object carrying a cycle still replays.

## Mutation controls

1. cycle check removed from the seam;
2. visited set dropped (must hang or recurse — killed by the termination test);
3. only `SERVES` checked, not `DERIVED_FROM`;
4. only `DERIVED_FROM` checked, not `SERVES`;
5. check runs at reduce/replay time instead of admission (breaks the legacy-cycle replay test);
6. self-edge permitted;
7. traversal depth capped at 1, so a three-node cycle passes;
8. the diamond DAG refused as a cycle (over-refusal is as wrong as under-refusal).

## Remaining decision

**None blocking IE2.2a.** For later slices, one item from §5 needs your call: whether the
evidential terminal set is `{OBSERVED, CANONICAL}` as ruled, given that `OBSERVED` is not
restricted to human assertion, or the stricter `{CANONICAL}`. IE2.2a does not depend on it.
